MVC

✅ Complete

Definition

MVC (Model-View-Controller) is an architectural pattern that separates an application into Model (data/state), View (UI/presentation), and Controller (input handling and coordination).

Why MVC Matters

It separates concerns clearly, making large applications easier to reason about, test, and maintain.

Syntax

class Model { /* data + business logic */ }
class View { render(data) { /* update UI */ } }
class Controller {
  constructor(model, view) { this.model = model; this.view = view; }
  handleInput(input) { /* update model, then tell view to render */ }
}

Examples

class TodoModel {
  todos = [];
  addTodo(text) { this.todos.push(text); }
}
class TodoController {
  constructor(model, view) { this.model = model; this.view = view; }
  addTodo(text) {
    this.model.addTodo(text);
    this.view.render(this.model.todos);
  }
}

Diagrams

User Input ──► Controller ──► updates ──► Model │ Model change triggers ▼ View (re-renders)

Internal Working

The Controller is the only layer allowed to know about both Model and View — the Model has no knowledge of the View, so it can be tested independently.

Common Mistakes

  • Letting the View directly modify the Model, bypassing the Controller.
  • Putting business logic inside the View.
  • Tightly coupling the Model to a specific View implementation.

Summary

MVC separates an application into Model, View, and Controller — improving testability and maintainability by keeping concerns cleanly separated.
