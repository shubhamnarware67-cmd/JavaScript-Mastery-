Hoisting

✅ Complete

Definition

Hoisting is JavaScript's behavior of processing variable and function declarations during the creation phase, before any code executes.

Why Hoisting Matters

It explains behavior like calling a function before its declaration, or getting undefined instead of a ReferenceError when accessing a var early.

Syntax

console.log(x); // undefined, not an error
var x = 5;

sayHi(); // works! function declarations are fully hoisted
function sayHi() { console.log("Hi"); }

Examples

console.log(typeof greet); // "function" (fully hoisted)
function greet() {}

console.log(b); // ReferenceError: Cannot access 'b' before initialization
let b = 2;

Diagrams

Creation Phase: var x ──► x: undefined function greet() ──► greet: [Function: greet] (fully hoisted) let y ──► y: <in Temporal Dead Zone>

Internal Working

let/const ARE hoisted, but remain in the Temporal Dead Zone until their declaration line executes, throwing a ReferenceError if accessed earlier.

Common Mistakes

  • Relying on var hoisting to use a variable before its declaration.
  • Assuming let/const are "not hoisted at all."
  • Assuming function expressions are hoisted the same way as function declarations.

Summary

Hoisting means declarations are processed during the creation phase — var becomes undefined, functions are fully hoisted, and let/const stay in the TDZ.
