Execution Context

✅ Complete

Definition

An execution context is the environment in which JavaScript code is evaluated and executed — holding info about variables, arguments, this, and the surrounding scope.

Why Execution Context Matters

It explains why variables are or aren't accessible at certain points, how this gets its value, and why hoisting behaves the way it does.

Syntax

console.log(x); // undefined (hoisting within this context)
var x = 5;

Examples

function regularFn() { console.log(this); }
const arrowFn = () => console.log(this);

regularFn(); // this = global object (non-strict) or undefined (strict)
arrowFn();   // this = whatever `this` was in the enclosing scope

Diagrams

Execution Context = { Variable Environment: { var declarations, function declarations } Lexical Environment: { let/const declarations, scope chain } this binding: depends on how the function was called }

Internal Working

Every execution context has two phases: a creation phase (hoisting, setting up this/scope chain) and an execution phase (code runs line by line).

Common Mistakes

  • Assuming let/const are hoisted the same way as var.
  • Confusing execution context with scope — related but distinct.
  • Misunderstanding how this is determined in regular vs arrow functions.

Summary

An execution context is JavaScript's environment for running code, created in two phases, determining variable hoisting, scope chain access, and this.
