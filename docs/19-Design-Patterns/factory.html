Factory

✅ Complete

Definition

The Factory pattern uses a function to create and return objects, encapsulating creation logic instead of requiring callers to use new directly.

Why Factory Matters

It centralizes and hides object-creation logic, making calling code simpler and easier to change later.

Syntax

function createShape(type) {
  if (type === "circle") return { type, area: (r) => Math.PI * r * r };
  if (type === "square") return { type, area: (s) => s * s };
}

Examples

function createNotification(type, message) {
  const base = { message, timestamp: Date.now() };
  switch (type) {
    case "error": return { ...base, icon: "❌", priority: "high" };
    case "success": return { ...base, icon: "✅", priority: "normal" };
    default: return { ...base, icon: "ℹ️", priority: "low" };
  }
}

Diagrams

createShape("circle") ──► { type: "circle", area: fn } createShape("square") ──► { type: "square", area: fn } (caller doesn't need internal construction logic)

Internal Working

The core value of a Factory is indirection — callers depend only on the factory's interface, not the concrete object shape being created internally.

Common Mistakes

  • Overcomplicating a simple object literal into an unnecessary factory function.
  • Duplicating default-value logic across call sites instead of centralizing it.
  • Confusing a Factory with a Constructor function.

Summary

The Factory pattern centralizes object-creation logic behind a function, hiding construction details — fits naturally into JavaScript's first-class functions.
