Garbage Collection

✅ Complete

Definition

Garbage collection is the automatic process by which JavaScript's engine reclaims memory from objects no longer reachable from any active scope.

Why Garbage Collection Matters

It removes the burden of manual memory management, though it doesn't eliminate the possibility of memory leaks entirely.

Syntax

let obj = { data: "large payload" };
obj = null; // removes the only reference, eligible for GC

Examples

function setup() {
  const heavyObject = { /* large data */ };
  function handler() { console.log(heavyObject); }
  window.addEventListener("resize", handler);
  // If never removed via removeEventListener, heavyObject leaks.
}

Diagrams

Roots: Global Object, active Call Stack frames │ Reachable objects (kept alive) │ Unreachable objects ──► garbage collected

Internal Working

Modern engines like V8 use a generational approach: most objects "die young," so a fast "minor GC" cleans young objects, while a "major GC" handles older survivors.

Common Mistakes

  • Assuming GC means memory leaks are impossible (still possible via lingering references).
  • Forgetting to remove event listeners or clear timers, keeping closures alive.
  • Holding references in long-lived caches without ever clearing unneeded entries.

Summary

Garbage collection automatically reclaims memory from unreachable objects using generational mark-and-sweep, but developers must still avoid patterns like forgotten event listeners that keep memory alive.
