Testing

✅ Complete

Definition

Testing in JavaScript means writing automated code that verifies your application behaves correctly — catching bugs before they reach production.

Why Testing Matters

Tests let you verify behavior instantly and repeatedly, catching regressions before users ever see them.

Syntax

test("adds two numbers correctly", () => {
  expect(add(2, 3)).toBe(5);
});

Examples

jest.mock("./api");
import { getUser } from "./api";
getUser.mockResolvedValue({ id: 1, name: "Alex" });

test("uses mocked API response", async () => {
  const user = await getUser(1);
  expect(user.name).toBe("Alex");
});

Diagrams

Testing Pyramid: ▲ E2E tests (few, slow) ▲▲▲ Integration tests (some) ▲▲▲▲▲ Unit tests (many, fast)

Internal Working

A test runner discovers test files and executes each test block, reporting pass/fail based on whether expect() assertions match.

Common Mistakes

  • Writing too many slow, brittle E2E tests instead of unit tests.
  • Not mocking external dependencies, making tests flaky.
  • Testing implementation details instead of observable behavior.

Summary

Testing verifies application behavior automatically, following a pyramid of unit, integration, and E2E tests.
