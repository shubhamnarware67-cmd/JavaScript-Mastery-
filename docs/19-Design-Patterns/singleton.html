Singleton

✅ Complete

Definition

The Singleton pattern ensures a class or module has only one instance throughout the application, providing a single global point of access.

Why Singleton Matters

It prevents accidentally creating multiple instances of something that should logically be unique — like a single app-wide config or connection pool.

Syntax

class Singleton {
  static instance;
  constructor() {
    if (Singleton.instance) return Singleton.instance;
    Singleton.instance = this;
  }
}

Examples

// counter.js — module-based singleton
let count = 0;
export function increment() { return ++count; }
export function getCount() { return count; }

Diagrams

First import of module.js ──► instance created, cached Second import of module.js ──► SAME cached instance returned

Internal Working

Because ES Modules execute top-level code only once, a plain exported object naturally behaves as a singleton — often simpler than the class-based approach.

Common Mistakes

  • Overusing Singletons for things that don't need to be globally unique.
  • Forgetting global mutable state can make tests unpredictable.
  • Reimplementing class-based Singletons when a module would work better.

Summary

Singleton guarantees only one instance exists app-wide — in JavaScript, often achieved through ES Module caching rather than explicit class-based checks.
