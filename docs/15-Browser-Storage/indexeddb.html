IndexedDB

✅ Complete

Definition

IndexedDB is a low-level, asynchronous, transactional browser database that lets JavaScript store significant amounts of structured data — including files and blobs.

Why IndexedDB Matters

localStorage is synchronous, string-only, and capped around 5-10MB — IndexedDB is asynchronous, supports structured objects and indexes, and can store much more data.

Syntax

const request = indexedDB.open("MyDatabase", 1);
request.onupgradeneeded = (event) => {
  const db = event.target.result;
  db.createObjectStore("users", { keyPath: "id" });
};
request.onsuccess = (event) => {
  const db = event.target.result;
};

Examples

function addItem(db, item) {
  const tx = db.transaction("items", "readwrite");
  tx.objectStore("items").add(item);
  return new Promise((resolve, reject) => {
    tx.oncomplete = () => resolve();
    tx.onerror = () => reject(tx.error);
  });
}

Diagrams

IndexedDB "NotesDB" (versioned) └── Object Store: "notes" ├── { id: 1, text: "Buy milk" } └── { id: 2, text: "Call mom" } (all operations wrapped in transactions)

Internal Working

All IndexedDB operations are wrapped in transactions and are asynchronous, communicating results via events (onsuccess, onerror) rather than return values.

Common Mistakes

  • Treating IndexedDB calls as synchronous instead of handling onsuccess/onerror events.
  • Forgetting to create needed object stores inside onupgradeneeded.
  • Not handling transaction failures, silently losing data on errors.

Summary

IndexedDB is a full-featured, asynchronous, transactional client-side database — far more capable than localStorage for structured, large-scale, or offline-first data.
