Modules

✅ Complete

Definition

Modules are self-contained files of JavaScript code that explicitly export and import functionality, allowing large codebases to be split into organized, reusable, independently maintainable pieces.

Why Modules Matter

Before modules, JavaScript files shared one global scope, causing naming collisions — modules give each file its own scope, with explicit control over what is shared and what stays private.

Syntax

// math.js
export function add(a, b) { return a + b; }

// main.js
import { add } from "./math.js";

Examples

// utils.js
export const PI = 3.14159;
export function square(n) { return n * n; }

// app.js
import { PI, square } from "./utils.js";
console.log(square(PI));

// Dynamic import
async function loadFeature() {
  const module = await import("./heavyFeature.js");
  module.init();
}

Diagrams

Each module = its own scope math.js { add, subtract } ──exported──► main.js imports only what it names (rest stays private to math.js)

Internal Working

Unlike scripts, ES Modules run in strict mode by default, execute only once no matter how many times imported (cached), and imports are live bindings.

Common Mistakes

  • Mixing CommonJS (require) and ES Modules (import) syntax without proper configuration.
  • Assuming a module re-runs its top-level code every time it's imported (it's cached).
  • Forgetting type="module" on <script> tags in the browser.

Summary

Modules let JavaScript code be split into self-contained files with explicit imports/exports, running only once regardless of import count, enabling build-tool optimizations like tree-shaking.
