Observer

✅ Complete

Definition

The Observer pattern defines a one-to-many relationship where a "subject" maintains a list of "observers" and notifies them automatically whenever its state changes.

Why Observer Matters

It decouples the object whose state changes from the objects that need to react to those changes — essential for scalable event-driven architectures.

Syntax

class EventEmitter {
  listeners = {};
  on(event, callback) {
    (this.listeners[event] ??= []).push(callback);
  }
  emit(event, data) {
    this.listeners[event]?.forEach((cb) => cb(data));
  }
}

Examples

const emitter = new EventEmitter();
emitter.on("userLoggedIn", (user) => console.log(`${user.name} logged in`));
emitter.emit("userLoggedIn", { name: "Alex" });

// Every DOM event listener is an Observer pattern:
button.addEventListener("click", () => console.log("Clicked!"));

Diagrams

Subject (EventEmitter) listeners: { "userLoggedIn": [callback1, callback2] } │ emit("userLoggedIn", data) ──► calls every registered callback

Internal Working

The subject holds no knowledge of what its observers do with the notification — this is exactly how addEventListener works under the hood.

Common Mistakes

  • Forgetting to provide an unsubscribe mechanism, causing memory leaks.
  • Letting observers directly mutate the subject's internal state.
  • Notifying observers with too little data, forcing them to re-fetch state.

Summary

The Observer pattern lets a subject notify many independent observers when its state changes — the foundational idea behind DOM events and state management libraries like Redux.
