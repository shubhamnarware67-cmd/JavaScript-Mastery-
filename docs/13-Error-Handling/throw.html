Throw

✅ Complete

Definition

The throw statement lets you manually raise a custom or built-in error, halting normal execution and passing the thrown value up the call stack until a catch handles it.

Why Throw Matters

It lets you enforce assumptions and validate inputs explicitly — instead of letting invalid data silently cause bugs later, you can throw immediately at the point something goes wrong.

Syntax

throw new Error("Something went wrong");
throw "a string";      // valid but discouraged
throw { code: 404 };   // valid but discouraged

Examples

// Beginner
function checkAge(age) {
  if (age < 0) throw new Error("Age cannot be negative");
  return age;
}

// Advanced: custom error class
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError";
    this.field = field;
  }
}

Diagrams

throw new Error("msg") │ Error object created: { message, stack, name } │ Execution stops, call stack unwinds │ Looks for nearest enclosing try/catch

Internal Working

throw immediately stops the current execution context and begins unwinding the call stack frame by frame, checking each enclosing scope for a try...catch.

Common Mistakes

  • Throwing plain strings or objects instead of Error instances, losing the stack trace.
  • Throwing generic Error for every case instead of custom error types.
  • Forgetting that a throw inside a Promise executor becomes a rejected Promise, not an immediately-catchable throw.

Summary

throw lets you manually raise an error — ideally an Error instance or custom subclass — immediately halting execution until a matching catch handles it.
