CORS

✅ Complete

Definition

CORS (Cross-Origin Resource Sharing) is a browser mechanism that lets a server explicitly declare which other origins can make requests to it, relaxing the Same-Origin Policy safely.

Why CORS Matters

Without it, the Same-Origin Policy would block ALL cross-origin requests, making SPAs calling separately-hosted APIs impossible.

Syntax

// Response headers
// Access-Control-Allow-Origin: https://example.com
// Access-Control-Allow-Methods: GET, POST

Examples

fetch("https://api.example.com/profile", {
  credentials: "include", // requires server: Access-Control-Allow-Credentials: true
});

Diagrams

Frontend: https://myapp.com API: https://api.example.com Browser blocks response UNLESS API responds with: Access-Control-Allow-Origin: https://myapp.com

Internal Working

CORS is enforced entirely by the browser — the server always processes the request, but the browser blocks JS from reading the response if headers don't permit it.

Common Mistakes

  • Assuming CORS blocks requests server-side (it's the browser blocking the response).
  • Forgetting to pair credentials: "include" with server-side Access-Control-Allow-Credentials.
  • Overly permissive CORS config exposing APIs broadly.

Summary

CORS lets a server safely permit specific cross-origin requests, enforced entirely client-side by the browser.
