Tree Shaking

✅ Complete

Definition

Tree shaking is a build-time optimization that removes unused exports (dead code) from the final bundle, based on statically analyzing ES Module import/export statements.

Why Tree Shaking Matters

It significantly reduces final bundle size by excluding code you import a library for but never actually use.

Syntax

// utils.js
export function used() { /* ... */ }
export function unused() { /* ... */ }

// app.js
import { used } from "./utils.js";
used(); // `unused` is dropped from the final bundle

Examples

import { debounce } from "lodash-es"; // tree-shakeable
// vs
import _ from "lodash"; // often pulls in the ENTIRE library

Diagrams

utils.js exports: { used, unused, alsoUnused } │ Bundler analyzes all imports across the app │ Only `used` is imported anywhere │ Final bundle: only `used`'s code is included

Internal Working

Tree shaking relies on ES Modules being statically analyzable — unlike CommonJS's dynamic require(), a bundler can build an accurate dependency graph at build time.

Common Mistakes

  • Importing an entire library's default export when only a few functions are used.
  • Writing modules with unintended side effects, preventing safe removal.
  • Assuming tree shaking works with CommonJS (it generally doesn't).

Summary

Tree shaking removes unused exported code by statically analyzing ES Module imports/exports, significantly reducing bundle size.
