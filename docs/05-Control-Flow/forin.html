For In

Section: Control Flow · Owner: Shubham Narware

Definition

for...in iterates over the enumerable property keys of an object (including inherited ones), making it suitable for plain objects but generally unsuitable for arrays.

History

Present since JavaScript's creation in 1995, predating for...of (ES2015) by two decades.

Why For In Matters

It's the classic way to enumerate an object's own (and inherited) property names — though modern code often prefers Object.keys/values/entries for more predictable, own-properties-only iteration.

Syntax

for (const key in object) {
  // use key, or object[key]
}

Types

Not applicable — single loop form, but worth contrasting with modern alternatives (Object.keys, Object.entries).

Examples

const user = { name: "Shubham", age: 22 };
for (const key in user) {
  console.log(key, user[key]);
}
// "name Shubham", "age 22"

Memory Diagram

Not applicable — control flow topic.

Flowchart

for (const key in object)
        │
Enumerate ALL enumerable properties
   (including inherited ones via the prototype chain)
        │
Assign each property NAME (string) to `key`
        │
Run body, repeat until no more keys remain

Internal Working

for...in walks not just the object's own properties but also enumerable properties inherited via its prototype chain — this is why hasOwnProperty() checks are commonly added when only the object's own keys are wanted.

Beginner Example

const car = { brand: "Toyota", year: 2022 };
for (const key in car) {
  console.log(`${key}: ${car[key]}`);
}

Intermediate Example

// Filtering to only the object's OWN properties
const obj = Object.create({ inherited: true });
obj.own = "yes";
for (const key in obj) {
  if (Object.hasOwn(obj, key)) { // modern equivalent of obj.hasOwnProperty(key)
    console.log("Own property:", key);
  }
}

Advanced Example

// Why for...in on ARRAYS is discouraged
const arr = [10, 20, 30];
arr.customProp = "extra";
for (const key in arr) {
  console.log(key); // "0" "1" "2" "customProp" — includes the non-index property too!
}

Real World Example

// Building a simple key-value summary of a config object
const config = { debug: true, retries: 3, timeout: 5000 };
let summary = "";
for (const key in config) {
  summary += `${key}=${config[key]}; `;
}
console.log(summary);

Industry Example

// Legacy codebases sometimes use for...in for quick object dumps/logging,
// though modern code favors Object.entries() + for...of or .forEach() for clarity.

Common Mistakes

  • Using for...in on arrays, potentially picking up unexpected non-index properties.
  • Forgetting inherited properties can appear in for...in, causing unexpected extra keys.
  • Assuming a guaranteed, consistent iteration order across all engines (mostly consistent in practice today, but not strictly guaranteed by spec for all key types).

Best Practices

  • Prefer Object.keys(), Object.values(), or Object.entries() combined with for...of/.forEach() for predictable, own-properties-only iteration.
  • Reserve for...in for cases where you specifically need to include inherited enumerable properties.

Optimization Tips

  • Object.keys/values/entries create an array upfront (slight memory cost) but offer clearer, safer semantics than for...in for most modern use cases — a worthwhile tradeoff in the vast majority of code.

Summary

for...in enumerates an object's enumerable property keys (including inherited ones) — useful for plain objects but risky for arrays; modern code generally prefers Object.keys/values/entries for clearer, own-properties-only iteration.
