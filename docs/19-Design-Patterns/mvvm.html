MVVM

✅ Complete

Definition

MVVM (Model-View-ViewModel) is an architectural pattern where the ViewModel exposes data and commands in a form the View can bind to directly, automatically syncing UI and state.

Why MVVM Matters

It eliminates the manual "update the View whenever the Model changes" boilerplate required in MVC.

Syntax

class ViewModel {
  #state = { count: 0 };
  #subscribers = [];
  get count() { return this.#state.count; }
  increment() {
    this.#state.count++;
    this.#subscribers.forEach((cb) => cb(this.#state));
  }
  subscribe(cb) { this.#subscribers.push(cb); }
}

Examples

// Vue-like computed property pattern
const vm = {
  firstName: "Ada",
  lastName: "Lovelace",
  get fullName() { return `${this.firstName} ${this.lastName}`; },
};

Diagrams

Model (raw data) ──► ViewModel (formats/exposes data + commands) │ Two-way binding / reactivity │ View (auto-updates)

Internal Working

MVVM relies on a reactivity system (like Vue's Proxy-based reactivity) that automatically tracks which View elements depend on which ViewModel properties.

Common Mistakes

  • Confusing MVVM's automatic reactivity with MVC's manual render-on-change approach.
  • Putting too much logic directly in the View instead of the ViewModel.
  • Creating overly complex two-way bindings that make data flow hard to trace.

Summary

MVVM introduces a ViewModel layer that exposes Model data through data binding, letting the View stay automatically in sync — the basis of frameworks like Vue and Angular.
